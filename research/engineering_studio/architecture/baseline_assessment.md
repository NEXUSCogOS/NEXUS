## Methodology

- **Execution log audit**: `IndependentAuditor.audit_historical_log(log_path='.nexus_execution_log.jsonl', sample_size=1000)`. Reads the first `sample_size` lines of the JSONL log, groups `code_lines` values by `directive`, and flags directives whose `code_lines` is constant across >=5 samples as evidence of fabricated (not genuinely measured) reporting. A sample of 1000 (not the full log, which is 2,766,535 lines) was used because the full log is very large; the sample size is fixed and documented here so a third party can rerun the exact same call and expect the same verdict on an unchanged log.
- **Directive backlog**: `measure_directive_backlog('.directives-ingestion')`. Real `os.scandir`/`os.stat` walk over the `pending/approved/in-progress/completed/rejected` subdirectories.
- **Storage sizes**: `measure_storage_delta('.nexus_execution_log.jsonl')` and `measure_storage_delta('systems')`. Real `os.stat` (file) / `os.walk` + `os.path.getsize` (directory) calls, executed at report-generation time.
- **Commit count**: `git rev-list --count HEAD` via `subprocess.run`, executed with `cwd` set to the repository root.
- **Python file count**: `Path('systems/engineering_studio').rglob('*.py')`, real filesystem walk, counted at report-generation time.
- **Execution log line count**: real line count via `open(...)` + generator sum over the log file, executed at report-generation time.

## Limitations

- This report audits the execution log's *internal consistency* (whether reported metrics vary in ways consistent with genuine per-directive measurement). It does NOT verify that the underlying claimed engineering work has independent business or technical value, nor that any given directive's described change actually happened as described.
- The execution log audit uses a sample of 1000 lines (from the start of the file), not the full file, for performance reasons; this is stated explicitly so the verdict's scope is clear. A different sample size or sampling strategy could in principle produce a different verdict.
- Storage and file-count measurements are point-in-time snapshots taken at report generation and will drift as the repository continues to change.
- Directive backlog counts only files present under `.directives-ingestion`'s five known subdirectories; files outside that structure are not counted.
- This report does not evaluate code quality, test coverage, or correctness of `systems/engineering_studio/` — only its raw size and commit-history activity.
